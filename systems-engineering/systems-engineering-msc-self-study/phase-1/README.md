# Phase 1 — Modeling languages and software-intensive systems

This phase establishes the two complementary modeling perspectives used throughout the program: system-level MBSE and software-level object-oriented analysis and design. It then applies them in Software Systems Engineering.

### Recommended order

1. [**EN.645.631 — Introduction to Model Based Systems Engineering**](en-645-631-introduction-to-model-based-systems-engineering.md)
2. [**EN.605.704 — Object-Oriented Analysis and Design**](en-605-704-object-oriented-analysis-and-design.md)
3. [**EN.645.764 — Software Systems Engineering**](en-645-764-software-systems-engineering.md)

EN.645.631 and EN.605.704 can be swapped or studied in parallel after Phase 0. Complete OOAD before Software Systems Engineering unless you already have strong software-analysis and design experience.

## Expansion status

| Course | Development status | Primary handoff |
|---|---|---|
| [EN.645.631 — Introduction to Model Based Systems Engineering](en-645-631-introduction-to-model-based-systems-engineering.md) | Fully expanded | Controlled MBSE repository, logical/physical architecture, V&V and change-impact evidence |
| [EN.605.704 — Object-Oriented Analysis and Design](en-605-704-object-oriented-analysis-and-design.md) | Fully expanded | Traced software requirements and use cases, integrated UML analysis/design model, state, patterns, OCL, persistence, and change-impact evidence |
| [EN.645.764 — Software Systems Engineering](en-645-764-software-systems-engineering.md) | Fully expanded | Traced software-system baseline, architecture and quality evidence, cloud/distributed and dependability analysis, CI/V&V, operations, and release-readiness package |

The expanded MBSE course continues the Autonomous Campus Shuttle Service baseline from Phase 0. It uses a dual SysML v1/v2 policy, but grades engineering meaning, traceability, repository quality, and decision support rather than diagram notation alone.

The expanded OOAD course narrows the same case to the Autonomous Campus Shuttle Operations Platform. It develops software requirements and use cases into static, dynamic, and state analysis models, then into responsibility-driven design, patterns, OCL constraints, persistence boundaries, change-impact evidence, and a defended final baseline.

The expanded Software Systems Engineering course integrates the MBSE and OOAD baselines into a controlled software product package. It develops system-to-software allocations, architecture viewpoints and decisions, agile release slices, quality-attribute evidence, cloud/service/distributed analysis, quantitative constraints, dependability and secure-development controls, reproducible Python/CI evidence, software V&V, operations, maintenance, and a defended release recommendation.
